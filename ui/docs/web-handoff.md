# Web 管理端交付说明

## 页面结构

- `overview`：全局运行摘要、最近部署和需要关注的异常。
- `deployments`：高密度历史列表、筛选与发起部署入口。
- `deployment detail`：日志是主工作区，元数据侧栏为次要上下文。
- `apps / nodes`：连续目录与详情页，不使用大面积卡片网格；节点由 Agent enrollment 自动创建。
- `agents`：管理员创建节点身份、复制短时安装命令，并维护在线连接与撤销状态。
- `deployment target`：在应用下管理环境、节点、脚本入口、受控参数、敏感引用和健康检查。
- `settings`：唯一管理员使用的用户、部署默认值和审计工作区。
- `setup`：全新实例的一次性管理员初始化；setup token 仅存在于提交中的表单内存。
- `login`：管理员分配账号的登录入口，覆盖失败和会话失效状态。

## 实现边界

- 正式组件应复用 `ui/docs/design-tokens.md` 的语义，不直接复制原型中的全局 CSS 类名。
- 路由刷新必须保留当前页面、筛选条件和已提交的 Mock 变更；正式实现应由服务端状态和查询参数替代设计源的 `localStorage` 覆盖层。
- 表格在窄屏隐藏低优先级列，但名称、状态和主要动作必须保留。
- 日志流需要独立管理连接状态、自动跟随状态和部署执行状态。
- 复制日志前由数据层完成敏感值脱敏，不能仅依赖视觉遮盖。
- 普通用户不得看到设置导航；直接访问设置路由时仍必须由路由和 API 返回权限不足。
- 设置主菜单展开系统设置、用户管理和审计记录二级菜单；工作区之间通过侧栏直接切换，不在内容区使用导航卡片。
- SSH 凭证与 host key 仅作为历史数据兼容，不进入正式 Web 日常导航或节点接入流程。
- Agent 创建后返回一次性安装命令；首次 enrollment 自动创建节点，节点页只展示 Agent 关联并下发 `SystemInspect` 能力检查。
- 普通用户授权在用户详情下使用独立路由，显式分配或撤销应用；客户端隐藏不能代替 API 对每个资源的授权检查。
- 应用、节点和部署目标的配置操作只对唯一管理员开放。
- Agent 管理仅对唯一管理员开放；客户端不持久化 enrollment token 或完整安装命令，不写入遥测。
- Agent 未关联或离线时禁止节点能力检查；任务失败必须保留节点详情并显示可定位的失败阶段。
- 应用归档后禁止发起新部署，恢复后重新开放；节点停用前展示受影响应用，停用后禁止被新部署选中。
- 新建、取消和重试部署必须形成独立任务状态；重试记录保留原任务关联，不能复用原任务日志或状态。
- 表单使用字段错误、表单错误摘要和首错聚焦；Agent 重新绑定或工作目录变化后节点能力检查失效，应用或目标的脚本调用配置变化后契约检查失效。
- 未保存修改必须拦截站内链接、浏览器历史和关闭页面；密码、secret 内容与完整敏感路径不得写入持久草稿。
- 停用用户、停用节点和归档应用先展示对象与影响；操作失败保持原领域状态并在原操作区重试。
- 列表显示当前结果数、筛选摘要、清空入口和“加载更多”；搜索重渲染后保留输入焦点。
- 日志上滚自动暂停跟随，跳到末尾恢复；复制、下载和重连失败不得清空已有日志，下载成功只表示请求已发起。

## 数据需求

- 部署摘要：ID、编号、状态、应用、环境、节点、版本、Revision、发起人、开始时间、持续时间和进度。
- 部署详情：阶段时间线、脚本入口、脱敏参数、退出状态和追加式日志。
- 应用：状态、环境、目标、节点、脚本入口和最近部署。
- 节点：在线状态、关联 Agent、工作目录、最近 SystemInspect、资源摘要和承载应用。
- 部署目标：环境、节点、固定脚本路径、契约状态、超时、受控参数、敏感变量引用和健康检查。
- 用户：固定身份、账号状态、最近活动和会话摘要；初始密码不回显或长期保存。
- 历史 SSH 字段：仅用于 legacy 查询和清理，不作为新页面或新部署的数据依赖。
- 应用授权：用户 ID、应用 ID 和授权状态。

## 响应式要求

- `980px` 以下详情侧栏进入主内容下方。
- `720px` 以下导航变为 icon rail；表格必须仍可完成定位和进入详情。
- 不把移动 App 的底部导航引入 Web 窄屏模式，两端属于独立产品形态。
