# UI 页面地图

## 设计原则

- 围绕“现在是否可部署、正在发生什么、失败在哪里”组织信息层级。
- 状态同时使用文字、图标和语义色，不只依赖颜色。
- 发起部署属于高影响操作，必须先展示目标和参数摘要再确认。
- 日志是工作内容，不放在装饰卡片中；需要支持持续滚动、暂停跟随和复制。
- Web 面向高密度管理，App 面向快速查看与操作，两端共享语义而非布局。

## 核心状态

| 对象 | 状态 |
| --- | --- |
| 节点 | 未检查、检查中、在线、检查失败、离线、凭证无效、已停用 |
| 应用 | 正常、部署中、异常、已归档 |
| 部署 | 排队中、运行中、成功、失败、取消中、已取消、执行中断 |
| 日志流 | 连接中、实时跟随、已暂停、已断开、已结束 |

### 桌面布局

- 左侧固定主导航。
- 设置激活时在侧栏展开系统设置、用户管理、SSH 凭证和审计记录二级菜单，内容区不使用功能卡片代替导航。
- 顶部承载当前页面标题、全局状态和主要操作。
- 列表页使用连续表格或列表，不把每一行做成独立大卡片。
- 部署详情采用摘要与日志主区域，宽屏可辅以执行元数据侧栏。

## App 管理端

### 一级导航

- 概览
- 资源
- 部署
- 我的

“我的”固定占用一级导航，承载账号身份、个人资料、偏好、系统管理和退出入口，为账号体系提供稳定入口。

权限模型固定为一个管理员和多个普通用户。系统管理能力只对管理员开放，不设计自定义角色、角色分配或多个管理员。

### 移动布局

- 一级页面使用底部导航，二级页面使用明确返回路径。
- 二级页返回固定映射：部署创建/详情到部署列表，应用与节点详情到资源根页，用户创建/详情到用户列表，用户列表及个人页到“我的”。深链与列表进入使用同一规则。
- 一级页面顶栏只显示页面标题，不显示副标题和账号头像；“我的”根页直接显示身份信息，不设置重复顶栏。
- 底部导航通过黑底白色图标、加粗标签和顶部短指示条共同表达选中状态。
- 移动端不定义鼠标悬浮反馈，只设计触摸按下、选中、禁用和焦点状态。
- 列表优先显示状态、名称和最近活动，低频元数据进入详情页。
- 长日志使用独立全屏阅读面，固定保留跟随 / 暂停和跳到末尾操作。
- 危险确认使用全屏或底部面板，不能仅用浏览器原生确认框。

## 路由与权限规则

- 未知路由和未知资源 ID 必须进入明确的未找到页面，不回退到入口或第一条 Mock 数据。
- 未登录访问业务路由时进入对应 Web / App 登录页。
- 普通用户不显示 Web 设置导航和 App 系统管理入口，通过深链访问时显示权限不足。
- 唯一管理员账号不能停用；普通用户由管理员直接创建和启停。
- SSH 私钥永不展示；公钥允许查看和复制，绑定节点的凭证必须先解绑才能删除。
- 节点由 Agent 首次 enrollment 自动创建；管理员从 Agent 页面生成安装命令，不在节点页手工录入 SSH 连接信息。
- 节点能力检查通过关联 Agent 下发 `SystemInspect`，Agent 离线或未关联时必须阻止检查。
- App 只展示节点的 Agent 在线状态与健康结果，不管理 enrollment token。

### 新增页面状态矩阵

| 页面 | Loading / Empty | Partial / Full error | Pending / Success | Failure / Retry | 403 |
| --- | --- | --- | --- | --- | --- |
| Web / App setup | 校验初始化状态时显示 loading；已初始化则跳转登录 | 状态读取失败保留重试入口，服务不可用显示整页错误 | 提交时禁用表单；成功清空 token 并进入登录 | token 无效或过期时就地报错并允许重新提交 | 已初始化实例禁止再次 setup |
| SSH 凭证列表 | loading 使用表格骨架；empty 引导生成第一组凭证 | 单行绑定摘要失败不阻断其他行；列表失败显示整页重试 | 删除请求 pending 时锁定对应行；成功后移除 | 删除失败保留原行；存在绑定时直接阻断 | 普通用户不显示入口，深链显示权限不足 |
| SSH 凭证生成 | 算法选项 loading 时禁用提交；无可用算法显示配置错误 | 不适用局部数据错误；依赖失败显示整页重试 | 生成时禁用表单；成功进入详情且不展示私钥 | 生成失败保留名称与算法并允许重试 | 普通用户深链显示权限不足 |
| SSH 凭证详情 | loading 使用详情骨架；资源不存在显示 not found | 绑定节点摘要可局部失败；主体失败显示整页重试 | 重命名、复制和删除分别显示 pending / success | 操作失败保留公钥与绑定状态并可重试 | 普通用户深链显示权限不足 |
| Agent 节点接入 | Agent 状态 loading 时禁用能力检查；未关联引导进入 Agent 管理 | Agent 辅助信息失败不阻断节点主体；主体失败显示整页重试 | 创建后显示安装命令；在线后允许下发 `SystemInspect` | Agent 离线、任务拒绝或超时均保留节点详情并允许重试 | 普通用户只读查看，Agent 入口和操作均不可见 |
| 用户应用授权 | loading 使用列表骨架；无应用显示 empty | 单项授权读取失败独立提示；列表失败显示整页重试 | 单项切换 pending 时禁用该项；成功刷新授权计数 | 失败恢复原 checkbox 状态并允许重试 | 普通用户与目标用户均不得进入管理页 |
| App 资源与节点详情 | loading 使用列表或详情骨架；无资源显示 empty | 单项健康状态失败不阻断列表；主体失败显示整页重试 | 重新检查显示 pending；成功刷新健康结果 | 检查失败保留最近成功结果并允许重试 | 无资源授权时隐藏条目，深链显示权限不足 |

## 关键交互流程

### 发起部署

```mermaid
flowchart TB
    Start[从部署或应用页发起]
    App[选择应用]
    Target[选择部署目标]
    Summary[核对节点、脚本与参数]
    Confirm{确认部署}
    Queue[创建排队记录]
    Detail[进入部署详情]

    Start --> App
    App --> Target
    Target --> Summary
    Summary --> Confirm
    Confirm -->|确认| Queue
    Confirm -->|返回修改| Target
    Queue --> Detail
```

### 运行与结果

```mermaid
flowchart TB
    Queue[排队中]
    Running[运行中并持续输出]
    Result{脚本退出结果}
    Success[成功]
    Failure[失败并定位最后输出]
    Interrupted[执行中断并人工核对]
    Cancel[取消中]
    Canceled[已取消]

    Queue --> Running
    Running --> Result
    Running -->|用户取消| Cancel
    Result -->|退出码成功| Success
    Result -->|退出码失败或连接异常| Failure
    Running -->|控制服务失去执行状态| Interrupted
    Cancel --> Canceled
```

## Mock 数据场景

- 空仓库：没有节点、应用和部署记录。
- 正常运行：同时存在排队、运行和成功部署。
- 部分异常：节点离线、部署失败、日志流断开。
- 高密度历史：多应用、多环境、大量部署记录和超长日志。
- 敏感参数：摘要与日志中以脱敏值展示。
- 加载中、筛选无结果、局部请求失败、服务不可用、会话失效和权限不足。
- 脚本契约失败、节点凭证无效、操作失败、日志工具失败、执行中断、日志断连和超长日志。

## 首轮评审路径

1. 从 Web 概览定位一个失败部署，进入详情查看最后有效日志。
2. 从应用详情发起部署，核对目标并确认，进入运行中详情。
3. 切换到 App，在部署列表找到同一记录并查看实时状态。
4. 查看离线节点及其受影响应用。
5. 切换空数据场景，检查两端的下一步操作是否明确。
