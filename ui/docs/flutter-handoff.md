# Flutter 管理端交付说明

## 导航

一级导航固定为概览、部署、应用、节点和我的。“我的”承载账号、固定身份、权限范围和设置入口。详情、部署确认和日志阅读都是二级页面，返回优先回到真实来源。

唯一管理员在“我的”页显示“用户管理”，普通用户隐藏整个系统管理分组。系统不提供自定义角色：管理员拥有系统管理能力，其他账号统一为普通用户。管理员账号不得被停用；普通用户由管理员直接新增、查看、启用和停用，不设计邀请或自行注册流程。

一级页面 AppBar 只保留标题，不展示副标题或右侧账号头像；“我的”根页不展示 AppBar，身份摘要使用无圆角、无阴影的全宽固定顶部栏。底部选中项必须同时改变图标底色、图标前景和文字字重，不能只依靠浅色背景。

## Widget 建议边界

| 设计组件 | Flutter 责任 |
| --- | --- |
| `Mobile Shell` | `Scaffold + SafeArea + NavigationBar` |
| `Mobile Resource Row` | 共享资源列表行，提供 leading、status 和 meta slots |
| `Status Badge` | 领域状态到 label、icon 和 color scheme 的统一映射 |
| `Summary Strip` | 可换行的两列摘要布局 |
| `Deployment Flow` | 可恢复的选择与确认状态，不把业务状态只放在页面局部变量中 |
| `Log Reader` | 独立滚动控制器、跟随开关、复制和跳到末尾 |
| `Confirmation Panel` | 使用 App 内 bottom sheet 或完整对话框，不调用浏览器式确认 |

## 行为要求

- 运行日志新增时，仅在用户处于跟随模式且接近末尾时自动滚动。
- 用户主动向上滚动即暂停跟随，点击跳到末尾后恢复。
- App 切到后台再回来时重新获取部署和日志状态，不能假定原连接仍有效。
- 深链进入详情时必须有稳定返回兜底，不能返回空页面。
- 用户提交的个人资料、通知偏好和管理员账号操作在刷新或进程恢复后应从服务端重新获取；设计源中的本地持久化仅用于预览这一行为。
- 新建部署、取消和失败重试必须使用独立任务状态；排队任务显示队列位置，重试任务显示来源任务。
- 节点重新检查需要区分检查中、成功、检查失败和凭证无效，并在返回详情后保留最近一次结果。
- 系统大字体下允许摘要换行，不压缩状态名称和主要动作。
- Flutter 端只实现 tap、pressed、selected、disabled 和 focus 状态，不为移动页面移植 Web 的 hover 样式。

## 跨端一致性

Flutter 必须沿用 Web 的黑、白、冷灰结构色、黄绿红灰状态色、状态名称、危险操作说明和脱敏规则，但不复刻桌面表格。移动列表只保留状态、名称、目标和时间，低频字段进入详情。
