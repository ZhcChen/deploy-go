# 独立远端开发环境

状态：完成；来源：2026-10-27 用户要求参考 Obsidian 远端 Compose 模板调整开发环境，特别避免 qfy-test2 正式环境冲突。

## 目标与范围

本机保留编辑、静态检查和单测，API/Web 装配与浏览器验收使用 qfy-test2 独立 Compose project。用户当前请求授权本项目独立开发环境的创建和验证，不覆盖其他 project、业务发布或正式服务操作。正式发布另由已有授权和正式 runbook 管理。

## 用户场景与验收

### US1：同机安全开发

开发者启动独立 API/Web 后可通过 SSH 隧道访问空库初始化页；正式 API/Web 的端口、数据、密钥与进程保持不变。重复启动只允许当前 owner 复用自己的 project，停止保留数据。

## 功能要求

- FR-001：显式 qfy-test2 context、完整 owner、分支、工作单元、用途和 session 后缀，所有 Compose 命令固定 -p/-f/--env-file。
- FR-002：零宿主发布端口，无 container_name、host network、external 资源、宿主 bind mount 或 Docker socket；独立内部网络与具名卷，不能访问正式数据库/密钥目录。
- FR-003：API/Web 使用 SHA 标识镜像并记录 image ID，代码通过 Git 快照/构建上下文传输；不修改其他项目或全局 Docker 状态。
- FR-004：开发密钥仅在 project 卷中生成，无明文输出；空库独立初始化，不导入正式数据/身份或接入业务 Agent；资源与日志有上限。
- FR-005：创建前核对资源和统一登记，拒绝 owner/分支/配置/镜像不匹配；同 project 单写入者，停止保卷，删除数据不提供通用入口。
- FR-006：同步仓库开发规范、运行手册与实际 Obsidian Vault 索引；后者链接统一登记表，不复制端口分配真值。

## 成功标准

- SC-001：离线渲染和拒绝危险配置回归通过；真实远端 API ready、Web/代理与 Playwright 初始化页验收通过。
- SC-002：正式 API/Web 的 PID、健康及端口在开发创建/停止/恢复前后保持一致。
- SC-003：停止保卷并恢复验证通过；登记镜像、归属、入口、状态与数据保留策略。

## 风险与验证要求

重点复核 context/owner、共享主机隔离、密钥权限、卷、错误恢复与数据保留。运行离线契约测试、Compose config、真实合成空库与浏览器验证；只读复核后修正并提交。
