# prepare 发布物传输可靠性与失败诊断

状态：本地实施与验证完成；真实发布及业务链路验收待完成
来源：2026-10-08 用户反馈及授权只读核查；证据见 research.md

## 目标与范围

让使用 Deploy Go 的人员能够知道构建后发布物传输失败的具体环节，并在故障得到修复后完成 prepare 到 release 的交接。本次故障中业务构建成功，但发布物传输失败，外部诊断只显示 agent_error，导致无法处理。

范围包含 deploy-go 自身的发布物传输、失败诊断、恢复语义和匹配验证。禁止修改业务应用代码、脚本、配置或发布物。没有证据时不调整全局网络策略、不增加超时或盲目重发部署；不把报告的前置检查总耗时直接归因于平台。

## 用户场景与验收

### US1：构建成功后能准确诊断传输失败

- 优先级：P1
- Given：业务构建脚本成功，后续发布物处理失败。
- When：用户查询同一部署的诊断与日志。
- Then：返回具体稳定错误码、失败环节与脱敏原因；区分脚本退出结果和平台交接结果。
- 关键失败或边界场景：上传初始化、分块、恢复查询、最终确认或鉴权失败；未知原因明确为未知；旧节点缺少详情时保持可查询，不编造原因。

### US2：传输故障恢复后可靠进入发布

- 优先级：P1
- Given：上传中出现连接中断或响应丢失，接收端可能已确认部分字节。
- When：平台在同一任务和既定有效期内恢复上传。
- Then：按接收端已确认进度继续，验证完成后才进入 release；不重复构建、重复发布或提前标为成功。
- 关键失败或边界场景：持续故障、取消、截止时间到达、错误进度、错误摘要、最终确认响应丢失和断线重连；均需有界并收敛到可解释结果。

### US3：分清等待发生在哪里

- 优先级：P2
- Given：用户报告发起前等待过长。
- When：核对请求、来源解析及任务阶段的时间证据。
- Then：区分调用前准备、服务端创建处理、prepare 脚本及发布物交接；缺少调用方证据时不宣称已定位其耗时原因。

## 功能要求

- FR-001：发布物处理失败的已知稳定错误码须在对外诊断中保留，未知或不安全内容继续使用通用错误，不泄露内部数据。
- FR-002：每次传输失败提供实际发生的环节、已知错误类别及可用的状态码、重试次数和耗时；无法确认的类别不得推断。具体原因可持久化并通过现有受权诊断查询。
- FR-003：构建脚本退出 0 但交接失败时，部署保持失败且不创建 release；诊断明确脚本成功不等于 prepare 成功。
- FR-004：恢复遵守任务截止时间、取消、授权有效期和接收端进度；禁止无界重试、跳过校验、重复构建或重复发布。
- FR-005：成功路径必须完成发布物传输、校验与交接；针对已复现的根因完成最小修复和回归，单独补齐日志不算实际故障修复。
- FR-006：所有新增日志、错误和诊断内容不得包含凭证、请求头、完整 URL、密钥、Env、内部绝对路径或响应正文；跨应用权限隔离保持不变。
- FR-007：升级期间旧 Agent、旧 CLI、历史无详细诊断记录仍可正常查询；保持现有状态、幂等键和日志游标语义。
- FR-008：按真实边界记录平台创建和发布物交接耗时，避免混淆前置准备与平台执行；性能修复只针对经测量确认的等待点。
- FR-009：只修改 deploy-go，自主本地验证；真实节点变更、控制面发布、Agent 更新及业务验证部署均按会话已有具体授权执行，不从规划批准推导新的运行权限。

## 成功标准

- SC-001：隔离环境中初始化、分块、恢复查询、最终确认、鉴权失败五类场景均返回可区分的稳定诊断；失败摘要无敏感测试标记。
- SC-002：至少一次约 60 MB 制品的正常交接和一次分块中断后的恢复完整通过；归档摘要一致，仅一次成功交接与 release 执行。
- SC-003：持续失败、取消、截止时间和异常进度测试均按既定预算收敛；不会提前成功或额外发起构建/发布。
- SC-004：完成独立复核及旧协议/客户端/无详情历史记录兼容验证；新增脱敏与访问隔离测试通过。
- SC-005：本次已证实的故障链路经授权真实验证后能够完成 prepare、release 及目标健康检查；未取得运行证据时只报告本地修复或诊断改善，不标记本次实际故障已解决。
- SC-006：输出可核对的平台耗时与证据边界；没有调用方时间线时不将 2 分 33 秒当作平台耗时或优化基线。

## 风险与验证要求

须有真实传输故障注入、端到端交接、错误透传/脱敏、截止时间/取消、身份权限和旧版本兼容验证；复用现有测试，不建立重型模拟框架。部署可靠性和敏感信息改动须独立复核，测试不能只镜像格式化函数。具体命令和文件范围见 plan.md。

## 未决事项

无待用户决定的需求歧义。HTTP 失败的底层网络原因尚未证实，这是实施前研究和复现任务，不以猜测消除；证据不足时保留未完成根因修复与真实验收任务。
