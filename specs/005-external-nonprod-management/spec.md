# 对外 API 与 Skill 最大化管理非生产应用

状态：就绪
来源：用户要求对外开放接口与 `deploy-go-deployer` Skill 对生产环境能力保持现状，并最大限度开放非生产应用的编辑、Git 来源处理、部署分支设置等能力；前序现状分析见 `docs/plans/2026-09-10-external-application-config-plan.md` 与 `docs/runbooks/external-deploy-api.md`。

## 目标与范围

让持有外部 API Key 的 AI 或脚本，能在不进入管理面的情况下，完整完成非生产（`dev` / `test` / `staging`）应用从接入到部署的闭环：配置 Git 来源、发现并选定部署分支、查询可用的构建 Agent 与 Git 凭证、管理应用启停与 Env 同步、查看配置文件元数据、预览并固定部署版本、触发运行状态探测。

分三个交付档位，按序推进，每档可独立验收和提交：

- P1：Git 来源写入、分支发现与轮询、设置部署分支、构建 Agent 与 Git 凭证只读目录、“Key 可用节点”白名单。
- P2：应用启停、Env 同步重试、非生产配置文件元数据读取（不含明文）。
- P3：部署预览与分支固定、运行状态探测。

明确不做：

- 不改变生产（`prod`）应用的任何现有对外行为；不新增对生产的写入、读取明文或部署能力。
- 不新增读取 Env 或配置文件明文的能力，Env 安全门禁保持现状。
- 不允许外部创建、轮换或删除 Git 凭证；不开放节点连接信息、工作根目录、密钥根目录。
- 不修改任何被部署的业务应用；不执行真实环境部署或节点操作。

## 用户场景与验收

### US1：为非生产应用配置 Git 来源并选定部署分支

- 优先级：P1
- Given：Key 绑定了一个非生产应用，且存在一条启用的 Git 凭证；如果管理员为该 Key 限定了节点，构建节点在其集合内。
- When：Key 查询可用构建 Agent 与 Git 凭证，保存 Git 来源（仓库地址、凭证、构建 Agent、物化配置），发起分支发现并轮询到完成，再设置其中一个分支为部署分支。
- Then：应用来源状态变为已验证，分支为所选分支，活动部署预览被作废；整个过程的响应、日志和审计不含凭证或密钥内容，审计记录带有该 Key 标识。
- 关键失败或边界场景：应用为 `prod`；构建 Agent 不在 Key 的可用节点内、离线或能力不足；凭证已停用；`version` 冲突；分支不在发现结果中；发现结果已过期；重复提交保存。

### US2：管理员限定 Key 可使用的节点

- 优先级：P1
- Given：管理员在管理面为某个 Key 配置了可用节点集合。
- When：该 Key 把 Git 来源、固定工作区来源或部署目标指向集合之外的节点。
- Then：请求被拒绝并返回稳定错误码；集合之内的节点正常；未配置集合的 Key 不得使用任何节点来写入上述三类配置，且既有已配置的应用不受影响，仍可按原配置部署。
- 关键失败或边界场景：节点被归档；集合变更后已存在的配置如何展示；目录接口只返回集合内节点。

### US3：在非生产环境管理应用启停与 Env 同步

- 优先级：P2
- Given：Key 绑定了非生产应用，其 Env 文件同步失败。
- When：Key 重试 Env 同步，或停用、启用应用。
- Then：同步被重新排队并返回实际状态；应用启停状态变化可查询；对 `prod` 应用同样请求返回 403。
- 关键失败或边界场景：同步无失败可重试；已停用应用的部署被拒绝；并发 `version` 冲突。

### US4：读取非生产应用配置文件元数据

- 优先级：P2
- Given：非生产应用有受管配置文件。
- When：Key 列出配置文件及其版本摘要。
- Then：只得到名称、版本、校验状态等元数据，不含任何配置内容或密钥值。
- 关键失败或边界场景：`prod` 应用返回 403；应用未启用配置工作区。

### US5：预览并固定部署版本、触发运行状态探测

- 优先级：P3
- Given：非生产应用已有已验证的 Git 来源或工作区来源。
- When：Key 生成部署预览并按预览确认部署，或请求一次运行状态探测并查询结果。
- Then：部署使用预览固定的提交；预览与探测结果可轮询；`prod` 应用的预览与探测请求返回 403。
- 关键失败或边界场景：预览过期或被作废；来源在预览后被修改；探测目标离线。

### US6：生产环境行为保持不变

- 优先级：P1
- Given：现有 20 个对外接口与全部新接口。
- When：对 `prod` 应用或目标逐一调用。
- Then：现有接口的响应、错误码与可见性与改动前一致；新增写接口、预览、探测一律返回 `external_production_application_forbidden`（或对应既有生产禁止码）。
- 关键失败或边界场景：应用环境由非生产改为 `prod` 的既有禁止规则；`cancel` 与只读诊断的既有行为不变。

## 功能要求

- FR-001：提供 Git 来源保存接口，字段与内部来源保存一致（仓库地址、可选 Git 凭证、构建 Agent、来源策略、物化配置），使用 `version` 乐观锁，首次创建返回 201，保存后作废活动部署预览。
- FR-002：提供分支发现发起与轮询接口；发起返回 202；结果按来源版本绑定并有过期时间；同一来源的重复发起要有限流或合并，避免堆积 Agent 任务。
- FR-003：提供设置部署分支接口，要求分支存在于未过期的发现结果中，使用 `version` 乐观锁，成功后来源状态为已验证并作废活动预览。
- FR-004：提供构建 Agent 只读目录，仅返回标识、名称、节点状态、协议与能力是否满足构建要求；不返回主机、端口、用户名、工作根目录等连接信息；仅列出该 Key 可用节点内的 Agent。
- FR-005：提供 Git 凭证只读目录，仅返回标识、名称、指纹、状态；不返回公钥与私钥；外部不得创建、轮换、停用或删除凭证。
- FR-006：引入可选的“外部 API Key 可用节点”限制，由管理员在管理面维护；管理员为某个 Key 配置了节点后，Git 来源、固定工作区来源、部署目标三处写入在保存时校验节点（构建 Agent 所属节点或目标节点）属于该 Key 的集合；**没有配置节点的 Key 不受限制，保持对外 API 的既有行为（2026-10-22 用户明确要求：本功能不得影响任何环境下的原有应用，修订原“默认拒绝”）**；已存在配置的部署行为不因该功能而改变。
- FR-007：白名单变更需要管理员权限并写审计；新增 migration 只追加，不修改任何已提交 migration，且不含 `DROP TABLE` / `DROP COLUMN`。
- FR-008：提供应用启停接口，仅限非生产应用；停用后该应用不可发起新部署，已运行部署不受影响。
- FR-009：提供 Env 文件同步重试接口，仅限非生产应用，不返回 Env 明文。
- FR-010：提供非生产应用配置文件元数据读取接口，不返回内容、密钥或差异正文。
- FR-011：提供部署预览生成与按预览确认部署的接口，仅限非生产应用；确认部署沿用既有两阶段部署语义和对外部署的非生产限制。
- FR-012：提供运行状态探测发起与结果查询接口，仅限非生产应用，结果只含脱敏状态摘要。
- FR-013：所有新增写接口、预览与探测在应用或目标环境为 `prod` 时返回 403 并使用既有生产禁止错误码体系；不新增任何对 `prod` 的读取或写入路径。
- FR-014：所有新增写入的审计记录带 `external_api_key_id`；凭证、Env、配置内容、lease 值不得出现在响应、日志、tracing、审计与 OpenAPI 示例中。
- FR-015：内部管理面对应 handler 的鉴权、CSRF、响应与审计行为保持不变；共用业务逻辑抽成核心函数，内外 handler 各自鉴权后调用。
- FR-016：对外 OpenAPI（`external.json`）、双端生成 client 与 `deploy-go-deployer` CLI 同步新增接口；CLI 新增子命令覆盖上述每个接口，Skill 的 `SKILL.md` 与 `references/` 同步写入边界、命令与错误码。
- FR-017：更新 `docs/runbooks/external-deploy-api.md` 与 `docs/standards/` 中相关契约，把“不向外部暴露 Git 凭证”修订为“仅暴露凭证元数据”，并写明节点白名单与生产不变承诺。
- FR-018：新增“生产不变”回归矩阵：覆盖现有 20 个接口和全部新接口对 `prod` 的预期，任何一项被意外放开应使测试失败。

## 成功标准

- SC-001：持有 Key 的调用方仅用 CLI 即可对一个全新的非生产应用完成“保存 Git 来源 → 发现分支 → 设置分支 → 预览 → 部署”的链路（本地 fixture 与模拟 Agent 验收，不连真实节点）。
- SC-002：生产回归矩阵 100% 通过；现有 20 个接口的 OpenAPI 对 `prod` 语义无变化。
- SC-003：对所有新增响应、日志与审计抽样断言，不含凭证、Env、配置内容与 lease 值。
- SC-004：已配置节点限制的 Key，三类配置写入对集合外节点 100% 被拒绝；未配置的 Key 与升级前行为完全一致（原有 `external_api` 用例不经任何修改通过）。
- SC-005：`make api-check`、`make agent-check`、`make admin-check`（含生成 client 漂移检查）、`make deploy-production-check` 与相关契约测试通过。
- SC-006：上线后的实际生效（正式环境部署、Skill 重新安装）属运维验收，不计入本地功能验收。

## 风险与验证要求

高风险项：权限边界、凭证与节点范围、migration、协议与 OpenAPI 契约，需要独立复核。

验证层级：

- API 集成测试（内存 SQLite + 模拟 Agent 消息）：每个新接口的成功路径、`prod` 403、`version` 冲突、白名单越权、响应不含敏感字段。
- 内部接口回归：沿用并扩展现有 `application_sources`、`application_workspace_sources`、`deployment_targets` 测试，证明抽核心函数后内部行为不变。
- migration 测试：`api/tests/migrations.rs`、`database_constraints`，并执行 `make verify-git-hooks`。
- OpenAPI 与 client：`make api-openapi-check api-client-check`。
- CLI 与 Skill：CLI 子命令的契约测试、帮助文本与 Skill 文档一致性检查。
- 管理面：白名单配置界面的组件测试与浏览器验证。
- 不连接真实节点，不执行真实部署。
