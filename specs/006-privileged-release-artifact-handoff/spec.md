# 特权发布制品交接契约修复

状态：本地实施、门禁与只读复核完成；现场未验收
来源：2026-10-27 用户转述的其他项目反馈及本地源码分析，基线 161f179

## 目标与范围

确保所有特权 release 携带已校验制品的下载授权，避免构建成功后因平台生成不完整任务而被 Agent 拒单。覆盖旧单目标 Git、workspace、多目标、镜像调度，失败诊断和历史任务恢复。

本次唯一入口为本目录。specs/001-prepare-artifact-transfer/ 已完成上传可靠性修复，本次引用其成果，不重开已完成任务；specs/004-privileged-release-monitor-recovery/ 的启动与终态恢复合同继续生效。

仅修改 deploy-go，不修改 Excel 等业务应用。本轮已授权本地实施，不授权真实节点读取、配置变更、升级、部署或业务重试。

## 用户场景与验收

### US1：构建后完成可信制品交接

- 优先级：P1
- Given：单目标 Git 或其他受支持路径完成构建。
- When：推进到 release。
- Then：先上传并校验制品，再生成绑定制品摘要、目标运行和 Agent 的下载授权，进入既有特权准入。
- 边界：同节点也必须交接；传输禁用、上传失败、制品缺失/过期/摘要冲突时不发送不完整任务。

### US2：失败可解释且恢复不重复发布

- 优先级：P1
- Given：历史任务缺少制品信息，或配置/能力不满足交接条件。
- When：调度、重投或查询诊断。
- Then：安全阻断并保留稳定错误码，不重跑构建、不重复发布、不复活失败部署。
- 边界：自动/手动放行、重连、API 重启、取消、终态重放、旧记录和旧客户端。

## 功能要求

- FR-001：每个特权 release 具有完整下载请求，绑定 verified 制品、摘要、目标运行和接收 Agent；同节点不例外。
- FR-002：旧单目标 Git prepare 必须完成上传和校验后才能推进 release；构建 exit0 不等于交接成功。
- FR-003：新任务入队和既有任务投递前验证制品契约；不完整任务不得发给 Agent，不伪造摘要/授权，不修改已持久化 payload/digest。
- FR-004：配置禁用或能力不足时以稳定、脱敏错误拒绝或结束，不无限等待、不回退低权限发布，保留 Agent 拒单保护。
- FR-005：下载 lease 限定制品、目标运行、Agent、用途和有效期；失败/取消按既有合同撤销，不泄漏 lease 值、Env、凭证或内部绝对路径。
- FR-006：保持幂等、手动放行、取消和终态不可回退；历史任务按真实状态分类，不误伤已接单/运行任务，不重复 ReleaseStart。
- FR-007：外部 API/CLI 保留 privileged_release_artifact_required 及本次必要门禁码，未知码继续泛化，不直通内部结果。
- FR-008：workspace、多目标、镜像、Env 门禁及既有授权/终态恢复不回归，优先复用现有协议与存储。
- FR-009：区分本地缺陷与历史现场归因；缺现场快照/版本证据时不宣称历史同因或现场已修复。

## 成功标准

- SC-001：旧单目标 Git 经真实 dispatcher、本地 HTTP 和 Agent 传输/准入完成上传、verified、下载，摘要一致且只有一次有效 release；覆盖同节点与不同节点。
- SC-002：配置禁用、制品缺失/未校验/过期、摘要或 lease 绑定不符、历史不完整任务均不能触发 ReleaseStart，并返回可解释结果。
- SC-003：四类路径、手动放行、取消、重启/重投、终态重放和权限隔离回归通过。
- SC-004：历史拒单码经外部 API/CLI 可见，旧记录与未知码兼容，新增诊断不含敏感信息。
- SC-005：本地门禁与独立复核通过后只标记本地完成；现场关闭另需具体授权和运行证据。

## 风险与验证要求

制品授权与历史恢复属于高风险边界。复用内存数据库、合成归档、本地 HTTP 和隔离 Docker fixture；至少一个真实调度到传输和准入用例，不能只断言字段非空。实施后安排独立只读复核，自审不称为独立复核。
