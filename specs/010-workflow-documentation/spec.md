# 工作流与文档首轮优化

状态：需求就绪；实施、验证和人工签收分别记录在 tasks.md。
来源：2026-10-31 用户确认执行工作流与文档分析建议的首轮范围；同日续作按用户决定移除强制独立复核。

## 目标与范围

让维护者和接手 Agent 快速确认项目现状、任务流程、验证要求和当前执行入口。首轮覆盖首页与导航、流程选择、验证映射和执行状态；补齐直接相关的 CLI 能力概览。

同日续作取消默认和强制独立复核，由实现者完成最终 diff 自审与匹配风险的验证；额外评审只在用户明确要求时安排。

本轮只调整项目文档、项目覆盖模板和本地检查编排，不改变产品运行行为、协议、权限、数据库或部署方式；保留历史正文、任务签收状态和外部规格存储。

## 用户场景与验收

### US1：从首页接手一项工作

- 优先级：P0。
- Given：维护者取得仓库，尚不了解历史计划和外部规格。
- When：从首页分别查找已知小缺陷修复、Agent 协议变更、旧任务续接的工作入口。
- Then：每种场景都能确定必读资料、短流程或完整流程、验证命令以及交付与签收边界。
- 关键边界：没有 Vault 配置时明确外部规格不可读，不建立同名副本；已有本地实现或发布记录不自动视为用户签收。

## 功能要求

- FR-001：首页描述当前能力和限制，使用可点击的当前文档入口；历史计划有明确的历史用途，CLI 概览覆盖已实现的命令类别。
- FR-002：按需求明确程度、范围和风险选择流程；恢复已定义行为的低风险局部修复可用短流程，权限、协议、schema、发布契约等变更仍走完整流程和对应验证。
- FR-003：统一记录改动范围到验证目标的映射，说明真实覆盖和额外检查；将既有 dev-remote-check 纳入 make check 并提供帮助入口。
- FR-004：提供当前任务及历史续接入口，分别表达实施、验证、发布与人工签收；历史状态只解释不批量改写，不创建全局活跃指针。
- FR-005：主要导航使用标准 Markdown 相对链接，文档门禁覆盖计划和规格索引；检查通过的含义与内容审核边界明确。
- FR-006：取消当前协作规则、原则摘要、覆盖模板和工作流中的默认或强制独立复核要求；实现者负责最终 diff 自审、匹配风险的验证与证据记录，额外评审只在用户明确要求时安排。保留已经发生的历史复核事实，以及权限、协议、migration 和运行授权边界。

## 成功标准

- SC-001：三种接手场景的桌面走查均有唯一执行入口、明确流程、验证组合及剩余边界。
- SC-002：文档、Spec Kit 和远端开发隔离检查通过，make check 的依赖包含 dev-remote-check。
- SC-003：所有任务勾选、历史签收和外部规格保持原状；本轮变更仅包含声明的本地文件。
- SC-004：当前规则与新任务模板口径一致，不再因风险等级自动要求另一位 Agent 复核；保留具体自审与验证要求，相关文档和 Spec Kit 检查通过。

## 风险与验证要求

复用 make docs-check、make spec-kit-verify、make dev-remote-check 和 make whitespace-check，核对 Make 依赖及三种文档阅读路径。没有生产代码改动，不运行真实节点操作，不把自审称为独立复核。
