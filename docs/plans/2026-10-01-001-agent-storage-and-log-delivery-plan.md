# 节点存储回收与可靠日志采集

## 目标与边界

只修改 Deploy Go。控制面集中保存部署日志，节点保留容量受限的断线补传缓存。
新机制以存储格式版本区分，升级后新建任务启用；旧任务继续兼容处理。
历史日志只在控制面明确确认完整接收后执行一次迁移回收，不以发送队列成功代替落库确认。
本轮授权为本地规划、实现、测试与提交；不据此操作真实节点或业务应用。

## 已核实证据

- 测试节点部署目录 25 GiB，抽样 checkout/staging 属主 runner、权限 2750；Agent 无组写权限。
- 升级失败每 15 秒重新创建任务、重复下载；测试升级目录 5.7 GiB。
- 生产 Executor cgroup 约 268 MiB，约 255 MiB 是文件缓存，RSS 约 2.9 MiB。
- `agent/src/task_handler.rs` 日志转发整文件读取，转发偏移推进不包含控制面落库 ACK。
- 普通任务已有 50 MiB 日志预算；不改变结构化事件、退出码和业务脚本协议。

## 复核结论

不能用 `result_sequence` 或时间判断历史日志已完整上传。新任务必须先持久化待发送消息，
由控制面确认连续序号后才回收缓存；日志与序号登记必须支持重复补传。
不能对任务文件执行外部 copytruncate。日志使用固定缓冲读取、受控分段，
删除仅作用于已确认分段；未知状态、未确认输出、活动任务和恢复元数据均保护。
旧日志迁移采用持久化版本标记与逐任务进度，崩溃后续跑，完成后不再次执行。
无法证明完整性的旧任务保留并明确记录原因，不伪造迁移成功。

## 执行单元

### U1：升级重试与升级缓存

- 相同 Agent/目标版本/manifest 的自动失败重试最多三次，按失败时间退避；手动重试独立。
- 新目标版本或新 manifest 可重新排队；归档节点继续排除，全局安装仍串行。
- 节点为每个升级任务保存终态，仅回收确认终态且超过保留期的下载缓存。
- 活跃升级及 updater 未决事务保持不动；历史无可靠状态的目录不盲删。
- 升级组件流式落盘、边接收边限额与校验，失败删除临时文件。
- 验证：连续扫描不产生重试风暴、退避到期恢复、手工重试、新版本、活跃目录保护。

### U2：部署目录权限回收

- 通过 Runner Broker 的固定任务 ID 回收请求，恢复与创建者一致的执行权限。
- Broker 自行读取受管 journal/spec，拒绝活动任务、未确认终态、活动同部署引用、越界和符号链接。
- 不接受调用者提供的任意路径，不放宽业务目录权限，不全局 chown/chmod。
- 验证：runner 所有的 2750 目录可回收；活动/越界/符号链接/待发布 staging 不删除。

### U3：日志持久化确认与有限缓冲

- 增加版本协商后的任务持久化回执，旧协议不发送新消息。
- 新任务的序号消息先落本地 durable outbox，再发送；ACK 后删除已确认缓存。
- 控制面连续序号、日志与事件登记的一致性检查，重传不产生重复日志或事件冲突。
- stdout/stderr 按偏移和固定缓冲读取；结构化事件与结果保持既有排序。
- 保持单任务预算，增加节点缓存总量保护；满额策略必须显式记录，不静默丢失。
- 验证：发送后断线、入队前崩溃、落库后 ACK 丢失、重复 ACK、乱序 ACK、旧协议。

### U4：分段与旧日志一次迁移

- 新任务日志采用版本化分段，默认段大小 4 MiB；按绝对偏移恢复，不对活动文件截断。
- 控制面确认后删除封闭分段，当前写入段与未确认段保护。
- 首次启动保存迁移版本及旧任务集合；后台小批次请求旧任务持久化证明。
- 只清理 stdout/stderr 与可再生发送缓存，不删除 journal、退出码、事件和业务日志。
- 未确认旧任务保留；重复启动与中途崩溃不重复删除，不阻塞上线。
- 验证：分段边界、重启续读、迁移中断、仅执行一次、缺确认保留、新旧任务并存。

### U5：集成验证与运维文档

- 聚焦 Agent/API/protocol/Executor 测试，格式、静态检查与独立审查。
- Linux 权限与断线 fixture 验证；本机不安装 Docker、不连接真实节点做变更。
- 更新恢复手册、协议和日志限制，记录回滚时保留新格式日志的要求。
- 每个验证通过的小闭环独立提交推送；原有两个未跟踪计划文件不纳入。

## 本轮执行记录

- U1 已实现：自动失败重试 60 秒/300 秒退避，三次后暂停；流式下载、按 job 保存状态、7 天缓存回收。交接给 executor 后必须取得 root updater 的终态证明，未知事务保护。
- U2 已实现：Runner Broker 仅接受任务 ID，核对 spec 属主/权限与终态后按创建者权限回收；清理校验不再要求已销毁的临时凭证存在。
- U3 已实现：v18 任务级交付标记、durable outbox、控制面持久化回执、幂等日志/事件投影、重连补传。ACK 使用独立有界队列，避免连接循环与发送锁互等。
- U4 已实现：新任务 stdout/stderr 按 4 MiB 分段，固定缓冲读取；连续 ACK 后回收封闭段，特权日志保留到结果 ACK。旧日志一次性登记为 retained，不重置偏移，不执行无证明删除。
- U4 方案调整：旧格式没有可验证的序号到原始字节映射，本轮不新增历史导入通道。历史日志无法证明完整上传时全部保留；一次迁移完成指登记完成，不代表历史日志已清空。
- U5 已完成本地测试、独立复核和运维文档；不包含真实节点部署、重启或历史目录清理。

实施限制：节点预算约束新格式缓存，不把历史 retained 日志算成可安全删除的数据。
保留的旧日志、未知升级目录和未决 updater 事务可能继续占用磁盘，需要后续明确的历史导入或人工核验流程。

## 发布与回滚说明

新日志能力仅协商成功后启用，旧节点维持旧行为。发布须提升成对组件版本，
节点按已有自动升级队列串行更新。真实发布与节点验证另按当前授权执行。
回滚前必须确认新格式任务已结束且日志确认完成；不能直接让旧 Agent 接管新格式活跃任务。

## 完成条件

上述执行单元全部实现且回归通过；未确认日志不得删除；旧应用部署无需修改。
真实节点峰值验收不以重启后的低值代替，需要独立授权与同等任务负载。
