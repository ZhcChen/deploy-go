# Admin App 体验补全与脚本契约计划

## 目标

- 让 Admin App 严格遵循移动交互，不出现依赖鼠标 hover 的状态。
- 收敛主 Tab 顶栏和底部导航，强化当前位置识别，移除重复账号入口。
- 补齐账号与 RBAC、应用脚本、节点检查、部署步骤等移动端高频页面。
- 形成可供 `qfy-voucher-hub` 等项目接入的通用部署脚本契约。

## 参考结论

- `qfy-voucher-hub` 已证明脚本需要同时输出人类日志和单行 JSON 事件，并保持退出码一致、参数白名单、失败阶段与恢复建议。
- 旧版 `easy-deploy` 的节点凭证、节点检查、应用环境/单元、预检、健康检查、任务阶段和 RBAC 值得保留，但复杂配置编辑不适合完整搬到 App。
- Admin App 优先覆盖观察、确认、检查和账号自助；Compose、`.env`、凭证原文和脚本编辑由 Web 承担。

## 执行单元

### U1：移动壳层

- 强化五项底部导航激活态。
- 主 Tab 顶栏只显示标题，不显示副标题和右侧头像。
- “我的”根页移除重复顶栏，直接以账号身份区开场。
- 二级页保留返回、标题和必要上下文，不显示头像。
- App CSS 中不定义 `:hover` 交互反馈，只使用 `:active`、选中、禁用和焦点状态。

### U2：高频页面

- 应用详情补部署目标、脚本契约状态和最近部署。
- 节点详情补能力、检查结果和“重新检查”。
- 部署详情补结构化步骤摘要和日志状态。
- “我的”补角色权限、个人资料、通知偏好和关于二级页。

### U3：脚本接入契约

- 编写 `docs/standards/deploy-script-contract.md`。
- 定义严格模式、白名单参数、环境变量、双轨输出、事件类型、退出码、安全、取消和预检规则。
- 在应用详情和部署步骤中体现脚本契约检查结果。

### U4：验证

- 验证所有 App 根页和二级页在 `390x844` 无溢出。
- 静态检查 App 样式不存在 hover selector。
- 验证五项导航、返回、脚本状态、节点检查和 RBAC 页面链路。

### U5：账号管理入口（已由 U6 收敛）

- “我的”根页增加用户管理入口。
- 补齐移动端用户列表、状态摘要和新增操作。
- 同步页面地图、Flutter 交付说明和浏览器路由验证。

### U6：固定身份模型与用户操作

- 移除自定义角色管理，只保留唯一管理员与普通用户两类固定身份。
- 系统管理功能仅对管理员显示和开放。
- 用户列表支持进入详情，普通用户支持启用与停用，管理员账号禁止停用。
- 补齐管理员直接创建普通用户的可提交交互。

### U7：管理员分配账号

- 移除邀请语义，不发送邀请、不提供用户注册流程。
- 管理员直接填写账号资料和初始密码，创建后立即分配为普通用户。
- 新账号创建后直接进入用户列表并可继续启用或停用。

## 完成结果

- U1 至 U4 已完成并落入 `ui/` 与 `docs/standards/deploy-script-contract.md`。
- U5 与 U6 已补齐用户管理交互，并收敛为唯一管理员与普通用户模型。
- U6 的用户详情、启停切换、管理员保护和账号创建流程已完成浏览器验证。
- U7 已移除邀请语义；管理员直接创建账号的表单、列表回写和固定普通用户身份已完成验证。
- U4 已通过静态语法检查、CSS selector 检查和浏览器逐路由布局检查。
- 本轮具体复核记录见 `docs/reviews/2026-07-31-app-ux-and-script-contract.md`。

## 非目标

- 不在 App 中编辑脚本、SSH 私钥、完整环境变量或 Compose YAML。
- 不直接复刻旧版 `easy-deploy` 的页面布局。
- 不在本阶段确定 API 的 SSH / Agent 最终执行架构。
