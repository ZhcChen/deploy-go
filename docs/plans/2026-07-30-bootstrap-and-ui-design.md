# 仓库初始化与 UI 设计计划

## 标题信息

- 任务：建立多模块仓库基线并完成首版 UI 设计源
- 状态：已完成
- 负责人：项目维护者
- 日期：2026-07-30

## 目标

- 明确产品边界、核心领域对象和四个模块的职责。
- 通过 `ui/` 交付可点击的 Web 与 App 管理端设计源。
- 在 UI 流程稳定后，为 `api/`、`admin/` 和 `admin-app/` 的工程初始化提供输入。

UI 设计的具体页面批次、组件、状态与验证要求见 `docs/plans/2026-07-30-ui-design.md`。

## 范围

- 整理根文档、产品需求、页面地图和设计约束。
- 创建纯 `HTML + CSS + JavaScript` UI 预览模块。
- 设计 Web 与 App 的核心管理、部署确认、运行日志和结果流程。
- 记录后续 API 架构必须解决的执行协议问题。

## 非目标

- 本计划不直接完成 Rust API、正式 Web 管理端或 Flutter App。
- 本阶段不连接真实节点、不执行真实脚本、不设计 CI/CD 流水线。
- 本阶段不扩展高级监控、告警、审批流、自动回滚和多租户能力。

## 影响区域

- 文件：`README.md`、`docs/brainstorms/`、`docs/plans/`、`ui/`
- 模块：仓库根目录、UI 设计源
- 接口 / 约束：UI 中的领域术语和状态需要成为后续 API 契约输入

## 阶段拆分

### 阶段 1：需求与信息架构

- 目标：收敛产品边界、对象关系、页面地图和跨端职责。
- 边界：只形成可评审文档，不实现业务模块。
- 验收重点：节点、应用、部署、日志四条主线无明显缺口。

### 阶段 2：设计基础与应用外壳

- 目标：建立 `ui/` 静态入口、tokens、共享组件以及 Web / App 预览壳。
- 边界：使用 mock 数据，不连接 API。
- 验收重点：桌面和常见手机视口无重叠、溢出和空白画布。

### 阶段 3：核心业务流程

- 目标：实现节点、应用、部署确认、运行日志和部署结果的可交互原型。
- 边界：交互只改变内存或 `localStorage` 中的 mock 状态。
- 验收重点：正常、空、运行、成功、失败、断连状态均可复现。

### 阶段 4：设计复核与工程交付

- 目标：完成视觉和流程复核，整理 tokens、组件清单及跨端交付约束。
- 边界：不在设计源中加入正式业务框架。
- 验收重点：后续 Web 与 Flutter 实现无需从截图猜测组件状态和页面关系。

## 执行单元

### 单元 1：需求基线

- 所属阶段：阶段 1
- 目标：完成产品需求、模块职责和首版边界文档。
- 涉及文件 / 模块：`README.md`、`docs/brainstorms/`
- 前置依赖：无
- 验证方式：逐项对照用户描述与首版需求编号。
- 完成标准：需求、非目标和待确认问题均有明确记录。

### 单元 2：页面地图

- 所属阶段：阶段 1
- 目标：定义 Web 与 App 的导航、页面和关键状态。
- 涉及文件 / 模块：`ui/docs/page-map.md`
- 前置依赖：单元 1
- 验证方式：从节点接入到部署完成走查主流程。
- 完成标准：两端都能覆盖一次完整部署及结果查询。

### 单元 3：静态设计源基线

- 所属阶段：阶段 2
- 目标：创建入口、路由、mock store、样式与跨端预览壳。
- 涉及文件 / 模块：`ui/index.html`、`ui/assets/`
- 前置依赖：单元 2
- 验证方式：本地静态服务与浏览器桌面 / 手机视口检查。
- 完成标准：入口、规范页、Web 预览和 App 预览可独立访问。

### 单元 4：核心页面与交互

- 所属阶段：阶段 3
- 目标：实现页面地图中的 P0 页面和状态切换。
- 涉及文件 / 模块：`ui/`
- 前置依赖：单元 3
- 验证方式：按推荐评审路径执行交互冒烟测试。
- 完成标准：部署前确认、运行日志、失败和成功流程均可演示。

### 单元 5：设计交付

- 所属阶段：阶段 4
- 目标：补齐设计 tokens、组件清单和 Web / Flutter handoff。
- 涉及文件 / 模块：`ui/docs/`
- 前置依赖：单元 4
- 验证方式：对照实际原型检查文档，无失效组件或路由。
- 完成标准：正式客户端能够基于文档和原型拆解实现任务。

## 建议执行顺序

- 先完成单元 1 和单元 2，再开始任何正式页面样式。
- 页面设计先做部署列表与部署详情，因为它们能验证跨端信息密度和状态语言。
- 再补节点与应用管理，最后补设置和低频辅助页面。
- 核心 P0 流程可操作后先进入一次 `review`，再扩展状态和交付文档。

## 验证方式

- 命令：使用 `make ui` 启动 Python 设计源服务器，默认端口为 `8050`。
- 手工检查：桌面 Web、窄屏 Web、移动设备外壳、键盘焦点和长日志滚动。
- 预期证据：通过 `http://127.0.0.1:8050/#/entry` 访问，页面地图中的 P0 路由均可用，主流程操作有稳定反馈，控制台无错误。

## 风险 / 待确认问题

- 节点执行采用 SSH 或 Agent 尚未决定，UI 暂时只表达连接状态与执行结果。
- 权限模型尚未决定，UI 首版不设计复杂角色配置。
- App 与 Web 功能“基本一致”不应解释为布局一比一复制；移动端需压缩低频配置。
