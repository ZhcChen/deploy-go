# 节点管理合并与 Web 主内容质感优化计划

## 目标

- Web 产品层只保留“节点”，Agent 作为节点内部协同程序展示和维护。
- 节点页面覆盖创建、安装命令、连接状态、版本、检查、重装和撤销，不丢失原 Agent 管理能力。
- 统一右侧主内容容器与原生数据表格视觉层级，延续 GitHub 黑白色系。

## 边界

- 本期不物理合并 `nodes`、`agents`、凭证和连接数据表，也不改 Agent 控制协议。
- 应用来源中的 `build_agent_id` 等内部 API 字段保持兼容；用户界面统一称为构建节点或节点协同程序。
- 不引入第三方 UI 组件库；继续使用现有 React 轻组件和语义化原生表格。
- `/agents` 旧地址保留兼容跳转，避免已有书签直接失效。

## 执行单元

### U1. 节点列表合并

- 把创建 Agent 流程迁入节点列表，并改为“创建节点”。
- 节点表格合并环境、协同程序版本、主机和最后在线信息。
- 移除独立 Agent 主导航。

### U2. 节点详情合并

- 在节点详情内展示协同程序运行信息。
- 迁入重新生成安装命令、撤销身份和确认交互。
- 保留历史 SSH 节点的协同程序接管入口和节点能力检查。

### U3. 主内容与表格视觉统一

- 将 `workspace` 设计为克制的主内容表面，不创建嵌套卡片。
- 强化表格外框、表头、行密度、悬浮/键盘反馈和操作列。
- 窄屏保持横向滚动，不让长路径、名称和操作重叠。

### U4. 兼容与验证

- 更新节点/Agent 管理测试和路由测试。
- 执行 `make admin-check`、`git diff --check`。
- 使用现有 Playwright 或浏览器工具完成桌面与移动截图复核。

## 完成标准

- 主导航不再出现独立 Agent，管理员可在节点页面完成原 Agent 高频操作。
- 普通用户仍只能查看授权节点，不请求或显示管理数据。
- 旧 Agent 深链有明确兼容行为。
- 所有列表页共享更清晰的主内容与表格视觉，桌面和窄屏无重叠。
