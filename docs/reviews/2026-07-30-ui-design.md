# UI 设计源复核

## 结论

UI 设计源已覆盖专项计划定义的 Web 与 App P0 页面、部署主流程、资源管理、共享状态、异常场景和交付文档，可以作为 `admin/` 与 `admin-app/` 的首版实现基线。

## 验证记录

- 使用 `make ui` 在 `127.0.0.1:8050` 启动成功。
- `/`、`assets/styles.css`、`assets/app.js` 和 `assets/mock-data.js` 均返回 HTTP 200。
- `ui/assets/app.js`、`ui/assets/mock-data.js` 和 `ui/tests/ui-preview.spec.js` 通过 Node 语法检查。
- Web 与 App 共 17 个 P0 列表 / 详情 / 操作路由均呈现正确壳层且包含有效内容，其中 App “我的”固定承载账号与 RBAC 入口。
- 浏览器控制台无错误。
- 部署确认能够生成 `#1043` 排队记录并进入详情。
- 取消部署经过二次确认，确认后移除取消动作并显示已取消状态。
- 日志断连场景保留已有输出，并明确说明部署任务可能仍在节点运行。
- 敏感参数仅以 `••••••••` 脱敏值呈现。

## 视觉检查

- `1440x900`：概览、部署详情与设计源工具条无重叠；日志主区和执行信息侧栏层级明确。
- `390x844`：概览、详情、长日志和固定取消操作无横向溢出或底部遮挡。
- Web 使用连续数据面，App 使用独立单列结构，没有把桌面表格直接缩放到手机。
- 首轮检查发现工具条遮挡页头、排队记录复用运行日志和移动二级页重复底栏，均已修正并重新截图确认。

## 剩余说明

- `ui/tests/ui-preview.spec.js` 已提供正式 Playwright 回归规格，但仓库当前未引入测试依赖，因此本次使用 `agent-browser` 完成等价的浏览器路由与交互验证。
- 设置、权限、节点接入表单和应用编辑表单属于专项计划明确排除的 P1 范围。
- SSH 或 Agent、权限模型和并发策略仍由后续 API 架构计划决定；设计源当前采用排队语义。
