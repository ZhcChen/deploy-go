# Admin App 体验与脚本契约复核

## 结论

本轮改动与计划一致。App 导航层级、移动交互状态、账号页和资源详情已补齐，部署脚本接入契约已形成独立规范。

## 核对结果

- 五项底部导航使用黑底白色图标、加粗标签和顶部指示条表达激活状态。
- 概览、部署、应用、节点一级页只显示标题，无副标题和右侧头像。
- “我的”根页无重复顶栏；身份摘要使用无圆角、无阴影的全宽固定顶部栏，下面的管理内容独立滚动。
- “我的”根页移除功能卡片上方的分组标题，将设置入口合并为一张连续列表卡片；卡片与退出按钮保持 `14px` 间距。后续导航收敛移除了独立“权限说明”入口。
- 退出登录使用浅红底、红字和浅红边框，避免纯红常驻按钮压过主要设置内容；纯红仅用于按下和确认状态。
- 身份权限、个人资料、通知偏好和关于页均可从“我的”进入。
- “我的”管理分组只向管理员提供用户管理入口；系统固定为唯一管理员与普通用户两类身份，不提供自定义角色管理。
- 用户列表可进入详情，普通用户支持启用与停用，唯一管理员账号受保护；管理员创建的账号固定为普通用户。
- 用户创建由管理员直接分配姓名、登录邮箱和初始密码，不发送邀请，也不提供自行注册入口。
- 应用详情展示部署目标、脚本入口、契约状态和最近部署。
- 节点详情展示系统、架构、运行能力、资源与重新检查操作。
- 部署详情展示预检、脚本执行、部署后验证和日志。
- `.app-preview` 下不存在 `:hover` selector，移动反馈使用 `:active`、选中、禁用和焦点状态。

## 剩余事项

- 当前为静态交互设计源，通知开关、节点检查和退出登录仅表达交互，不连接真实 API。
- 脚本契约当前为 Schema v1 草案，API 执行器实现时需要补 JSON Schema、超时上限和取消退出码常量。
