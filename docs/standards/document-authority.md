# 文档权威性与历史隔离规则

本文约束仓库内不同类型文档的权威顺序，避免历史计划、阶段总结或旧排查记录被误当成当前实现依据。

## 当前口径优先级

默认按以下顺序判断：

1. 当前对话中的用户明确指令。
2. 仓库根目录 `AGENTS.md`。
3. `docs/standards/` 下的通用与专题规范。
4. `docs/runbooks/` 下的运行、部署、迁移、排障和联调手册。
5. `docs/solutions/` 下已明确当前结论、历史漂移或架构边界的沉淀文档。
6. `docs/plans/` 下仍处于 active 状态的计划文档，但计划只用于当前任务拆解和执行，不得覆盖以上规则。
7. 已完成计划、阶段总结、历史任务清单和历史排查记录，仅作为背景材料，不作为当前实现或运行规则的直接依据。

代码、测试和旧文档冲突时，应先根据运行行为和更高优先级文档确认当前事实，再更新已经漂移的文档；不得仅凭历史计划覆盖当前实现。

## 历史文档标记

- 已结束的计划不得继续保留 active 状态。
- 阶段总结、临时任务清单和排查记录应说明它们属于历史背景还是当前规范。
- 文档被新方案替代时不强制删除，但应标记已归档，并指出当前应优先参考的文档或代码位置。

## 维护要求

- 新增规范、手册或方案时，引用路径统一使用仓库相对路径。
- 运行、部署、迁移、排障和联调结论应沉淀到 `docs/runbooks/` 或 `docs/standards/`，不能只保留在一次性计划中。
- 发现旧文档仍被频繁引用但内容已经漂移时，优先补充历史漂移说明，再决定是否拆分新文档或归档旧文档。
