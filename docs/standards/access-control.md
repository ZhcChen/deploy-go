# 访问控制规范

## 目的

本规范统一 `api/`、`admin/` 与 `admin-app/` 的首版权限边界。系统不建设自定义 RBAC，只保留一个不可删除的管理员和多个普通用户。

## 固定身份

| 身份 | 数量 | 能力 |
| --- | --- | --- |
| 管理员 | 全系统唯一 | 管理节点、应用、部署目标、普通用户、系统设置和审计；可执行全部部署操作 |
| 普通用户 | 零个或多个 | 查看已授权资源、发起部署、查看日志、取消允许的任务和失败重试 |

- 不提供角色管理、角色创建、角色分配或第二个管理员。
- 管理员账号不能被停用、删除或降级。
- 普通用户由管理员直接创建，固定为普通用户身份。
- 不提供邀请、自行注册或普通用户自行提升权限的入口。

## 功能边界

| 功能 | 管理员 | 普通用户 |
| --- | --- | --- |
| 查看概览、部署、应用和节点 | 允许 | 允许，受资源范围约束 |
| 发起、取消和重试部署 | 允许 | 允许，受资源范围约束 |
| 新增或编辑节点、应用和部署目标 | 允许 | 禁止 |
| 用户管理、系统设置和审计 | 允许 | 禁止 |
| 修改个人资料和通知偏好 | 允许 | 允许 |

普通用户的具体资源授权模型留给 API 设计阶段确定；在此之前，客户端使用“已授权资源”表达，不虚构自定义角色或权限编辑器。

## 强制规则

- 权限必须在 API 层执行，客户端隐藏入口只能作为体验优化。
- Web 和 App 路由必须处理未登录、会话失效和权限不足，不能回退到首页或空数据页。
- 停用普通用户后应使其现有会话失效，但不得删除历史部署和审计记录。
- 初始密码仅在创建或重置时提交，不在列表、详情、日志或 Mock 持久化状态中回显。
- 用户创建、启停、初始凭证重置和系统配置变更必须写入审计记录。

## 对外 API Key 边界

对外部署 API（`/external/v1`）使用独立的 API Key，与用户会话完全隔离；它不是第三种用户身份，权限由两道限制叠加：

- **应用范围**：Key 只能访问管理员绑定的应用。
- **环境限制**：所有写操作只允许非生产（`dev` / `test` / `staging`）应用；`prod` 应用统一拒绝。只读查询、部署诊断与取消部署的既有行为不变。

对外新增的只读接口（Git 来源详情、分支发现记录、配置文件元数据、运行状态）同样不对 `prod` 应用开放，既有只读接口对 `prod` 保持原行为。归档的应用只能由归档它的同一个 Key 重新启用。

对外保存 Git 来源时仓库地址有更严格的策略（只允许 ssh/https，https 不含用户信息，拒绝本机与内网 IP 字面量），只作用于对外这一个入口，不影响管理面与已保存的来源。

对外 API 不提供 Env、配置内容或凭证内容的读取。Git 凭证仅暴露 id、名称、指纹和状态，外部只能引用，不能创建、轮换、停用或读取。外部写入的审计记录带 `external_api_key_id`。

## UI 表达

- 普通用户不显示 Web 设置导航和 App 用户管理入口。
- 管理员详情显示唯一管理员保护说明，不显示停用或身份变更操作。
- 权限不足使用独立反馈，并提供返回业务首页或“我的”的入口。
- 界面统一使用“管理员”“普通用户”“身份”“权限范围”，不使用“角色管理”。
