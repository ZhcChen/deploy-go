# plan 提示词

适用场景：开始正式做任务，需要明确目标、范围、实施路径和验证方式。

## 可直接粘贴给 Codex

请把这次请求当作一次 `plan` 阶段，输出一个可执行的轻量计划，并优先落到 `docs/plans/`。

用户输入：`[把这里替换成任务描述、需求、关联文件或上游结论]`

执行要求：

- 这是计划阶段，不直接开始大规模实现；重点是目标、范围、影响区域、实现思路、验证方式和风险
- 优先复用已有 `docs/plans/` 正式文档；如果没有合适文档，参考 `docs/plans/TEMPLATE.md` 新建具体文件
- 如果上游已经有相关 `docs/brainstorms/` 收敛结果，先吸收后再写计划
- 不把正式内容直接写进 `docs/plans/TEMPLATE.md`
- 文档统一使用简体中文，并在涉及文件、模块或命令时使用仓库相对路径或明确命令
- 计划至少覆盖：目标、范围、非目标、影响区域、实现思路、验证方式、风险 / 待确认问题、沉淀跟进
- 如果任务明显偏大，必须拆成“阶段 + 执行单元”，不要只给一个笼统总计划
- 每个执行单元至少写清：目标、涉及文件 / 模块、前置依赖、验证方式、完成标准
- 结束时给出计划文件路径，并说明下一步应从哪个阶段或执行单元进入 `execute`
