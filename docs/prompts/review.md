# review 提示词

适用场景：改动完成后，需要对照计划复核结果并检查回归或偏差。

## 可直接粘贴给 Codex

请把这次请求当作一次 `review` 阶段，对照相关计划和当前改动做结果复核。

上下文：

- 计划文件：`[替换为 docs/plans/... 路径，没有可删]`
- 本次改动范围：`[替换为文件、模块、PR 或需求说明]`
- 是否需要落文档：`[是 / 否；若需要，写入 docs/reviews/]`

执行要求：

- 优先找到对应的 `docs/plans/` 计划；如果没有明确计划，先说明将依据什么目标或改动范围来复核
- 至少执行聚焦验证，并检查明显回归、范围漂移、遗漏和与计划不一致的地方
- 先给出最重要的发现或结论，再补充验证依据；不要把无关日志原样堆出来
- 如果结果符合计划，明确说明哪些证据支持这一判断
- 如果存在偏差，明确区分：必须修正的问题、可接受的残留项、建议后续沉淀的内容
- 如果要求保留 review 记录，参考 `docs/reviews/TEMPLATE.md` 写正式文档
