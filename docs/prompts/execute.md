# execute 提示词

适用场景：已有正式计划，准备开始实施或继续推进某个阶段 / 单元。

## 可直接粘贴给 Codex

请把这次请求当作一次 `execute` 阶段，基于现有计划开始实施，而不是重新写一份计划。

上下文：

- 计划文件：`[替换为 docs/plans/... 路径]`
- 当前阶段 / 单元：`[替换，没有可删]`
- 补充说明：`[替换，没有可删]`

执行要求：

- 优先找到并理解对应的 `docs/plans/` 正式文档；如果缺少明确计划，先说明并建议转到 `plan`
- 只承接当前阶段或一组连续、强相关的执行单元，避免把整个大任务一次吞下
- 按小步、可验证方式实施改动，避免无关重构；涉及文件时使用仓库相对路径
- 完成一个执行闭环后先验证，再决定继续下一个单元还是进入 `review`
- 实施过程中持续保留验证证据；如果发现范围扩张、依赖变化或关键假设被推翻，先显式记录
- 结束时明确说明：完成了什么、跑了什么验证、当前完成到哪个阶段 / 单元、下一步继续执行还是进入 `review`
