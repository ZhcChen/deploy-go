# 应用配置唯一编辑入口收敛

## 问题定义

管理端目前存在多个看起来像“Env/配置”的入口：应用详情里的「应用 Env」、
目标编辑器里的「敏感文件引用」、模板页的 Env 示例、目标详情与节点详情里的
「环境」。这些概念实际语义不同，但 UI 没有区分，导致管理员不清楚配置应该
在哪里维护，也容易出现目标级配置漂移。

## 现状事实

- `application_env_files` / `application_env_versions` / `application_env_syncs`
  是当前应用 Env 的权威模型：逻辑对象、不可变加密版本、逐目标同步事实。
- Agent 节点上的 `secrets_root/<application_slug>/*.env` 是同步结果，
  release 任务内的 `env/` 是运行期副本，都不是编辑入口。
- `secret_file_references` 只进入旧单脚本任务 `DeploymentExecuteTask`，
  只传绝对路径、不读取内容；`two_stage` 和特权 release 不使用它。
- `deployment_targets.environment` 已是只读兼容值 `prod`；
  `agents.environment` 是节点分类标签，与业务 Env 无关。
- 模板 `*.env.example` 是业务仓库示例，不是运行配置。

## 原则

1. 一个应用代表一个环境实例，运行配置归属应用，不归属部署目标。
2. 节点文件是同步结果，不允许在节点上作为第二编辑入口。
3. 配置按“是否随代码发布”和“是否敏感”分类，每类只有一个编辑入口。
4. 平台元配置（目标、参数 Schema、节点分类）与业务运行配置分开展示。
5. 旧能力保持兼容，但不再在常规 UI 中制造第二配置入口。

## 唯一编辑入口划分

### A. 随代码发布的普通配置文件

包括 `compose.yaml`、`config/*.conf`、发布脚本、模板源码等。

- **唯一编辑入口：业务 Git 仓库。**
- Deploy Go 通过 prepare 制品只读校验和发布，不提供这些文件的编辑页。
- 模板页只读展示示例，方便复制到业务仓库。

### B. 环境运行配置（Env）

包括 `compose.env`、`api.env`、`worker.env`、`postgres.env` 等运行期配置。

- **唯一编辑入口：应用详情 → 应用配置。**
- 加密存储、版本化、保存后同步到该应用的全部目标节点。
- 敏感文件（dotenv）查看/编辑前要求管理员重新验证密码。
- Web 不提供“目标级 Env”编辑；旧 `secret_file_references` 从常规路径收敛。

### C. 平台元配置

包括节点、Agent 环境分类、部署目标、执行参数 Schema、验证配置。

- 入口分别在节点/Agent 管理、目标编辑、部署发起页。
- 与业务运行配置不同，这些是调度和执行参数，不归入应用配置编辑器。

## 应用配置页设计

把现有「应用 Env」升级为「应用配置」的统一入口，首版只承载 dotenv 文件：

1. 文件列表：文件名、module、format、当前版本、digest、逐目标同步状态。
2. 编辑器：结构化键值表格 + 原文编辑器，两种模式编辑同一份文档。
3. 敏感保护：dotenv 需要短期明文授权；普通配置格式后续按需分级。
4. 保存流程：校验 → 版本化 → 全目标同步 → 展示每个节点结果。
5. 创建/导入：首版仍由业务仓库 prepare 首次登记；后续增加模板示例导入和
   管理员登记，但编辑入口仍然只有这里。

## 收敛项

- 目标编辑器的「敏感文件引用」只在 `script` 单脚本模式显示，并标注为
  legacy；`two_stage` 下隐藏。
- 模板创建向导移除 `secretReferences` 输入，模板目标固定走
  `two_stage` 配置。
- 目标详情把「环境」改为“兼容环境标识”或隐藏，避免与运行配置混淆。
- 节点页「环境」保留为节点分类，并注明不影响应用 Env。
- 应用详情区块标题从「应用 Env」改为「应用配置」，说明“所有目标节点自动
  同步，无需在目标上重复配置”。

## 后续扩展与开放问题

- 是否支持 Web 新建/导入配置文件，以及从模板一键生成初始版本。
- 是否扩展非 dotenv 格式（JSON、YAML、conf），以及各自的校验、加密和
  同步策略。
- legacy 单脚本模式是否长期保留 `secret_file_references`；不保留时再走
  正式计划移除。
- `agents.environment` 是否继续作为节点分类保留，或后续移除。

## 建议实施顺序

1. UI 收敛：统一「应用配置」入口，隐藏 two_stage 下的敏感文件引用，模板
   向导移除旧引用输入。
2. 术语与文档收敛：更新 runbook、OpenAPI 注释和模板说明。
3. 模型扩展决策：Web 登记/导入、非 dotenv 格式、legacy 字段去留，单独进入
   brainstorm/plan。
